# 수습 기간 (job-handoff)

이 스킬은 **주인의 업무 1개를 AI 직원이 혼자 할 수 있을 때까지** 가르친다. 핵심은 하나다: **말로 고치면 다음 대화에서 잊는다. 설명서로 고쳐야 남는다.**

```
인터뷰(총괄) ─▶ 설명서 v1 ─▶ 사례 3개 ─▶ 되말하기(담당) ─▶ 매일 보고 ─▶ 👍 ✏️ ❌ ─▶ 설명서 고침 ─▶ 승급
```

주인에게는 주인의 언어로 쉽게 말한다. **주인에게 파일 경로·id·JSON·영어 오류문을 보여 주지 않는다.** 스크립트 출력의 `message` 를 그대로 전하면 된다.

## 0. 먼저 알아둘 것 (에이전트용)

- 모든 명령은 `node <skill-dir>/scripts/<이름>.mjs --main <총괄 작업 폴더 절대경로> …`. `<skill-dir>` 는 이 SKILL.md 가 있는 폴더.
- 팀 명단은 `openclaw agents list --json` 으로 읽는다. 안 되는 환경이면 `start` 에 `--team <팀 JSON 절대경로>`(`[{"id":"main","workspace":"/절대/경로"}, …]`).
- 대시보드(openclaw-personal-dashboard)를 쓰면 보고가 「수습」 메뉴에 올라간다. 장부 기본 위치는 `~/.openclaw/workspace/dashboard/ojt.json`(대시보드 폴더가 있을 때만 쓴다). 다른 곳이면 `--dashboard <절대경로>`, 끄려면 `--dashboard none`.
- **업무 폴더는 담당 직원의 작업 폴더 안 `jobs/<업무 id>/`** 에 생긴다. 담당 직원의 AGENTS.md 에 "이 업무는 설명서 먼저" 안내가 자동으로 들어간다.
- 업무 id 는 영문 소문자·숫자·하이픈(예: `ad-log`). 주인에게는 업무 이름으로만 말한다.
- **설명서·묻기 규칙·배운 것·채점표는 직접 고치지 않는다.** 반드시 스크립트로, **주인이 승인한 뒤에.**
- 수습 업무에서 받은 채점·교정은 이 스킬로만 처리한다. **성장 노트(self-improve)에 같은 교정을 메모하지 않는다.** 모든 일에 통하는 습관(말투·보고 형식 등)은 성장 노트로 간다.
- 비밀번호·카드번호·고객 실명·연락처를 설명서·사례·보고에 쓰지 않는다. 스크립트가 일부를 `[가림]` 으로 가리지만 믿지 않는다.
- 하지 않은 일을 했다고 말하지 않는다. 오류는 12절 표대로.

## 1. 인수인계 시작 (총괄)

주인: "광고분석가에게 쿠팡 광고 일지 업무 인수인계 시작해 줘"

1) 업무가 **딱 1개**이고 자주 하는 일인지 확인한다. 여러 개를 말하면 "하나만 먼저 해요. 가장 자주 하는 건 무엇인가요?" 담당이 없으면 팀원 중 어울리는 직원을 제안하고 확인받는다.
2) 시작한다.
```bash
node <skill-dir>/scripts/start.mjs --main <main> --id ad-log --title "쿠팡 광고 일지" --agent <담당 직원 id>
```
3) **인터뷰 7문항을 한 번에 하나씩** 묻는다. 묻는 법·되묻는 법·좋은 답의 기준은 [`references/interview.md`](references/interview.md). 답이 흐릿하면 넘어가지 말고 되묻는다("매일이면 몇 시쯤이에요? 왜 그 시간이에요?").
4) 답을 설명서 모양(`## 1.` ~ `## 7.`)으로 정리해 임시 파일에 쓰고, **주인에게 요약을 보여 주고 "이대로 저장할까요?"** → 승인되면:
```bash
node <skill-dir>/scripts/job.mjs --main <main> --id ad-log --file /tmp/ad-log-job.md --reason "인터뷰"
```
`warnings` 가 있으면 주인에게 쉬운 말로 알린다(빠진 질문은 다시 묻고, 1,500자가 넘으면 "예시는 사례로 옮길까요?").
5) **기준 시간을 묻는다.** "이 일을 대표님이 직접 하시면 1건에 몇 분쯤 걸리나요? 어림이면 돼요." 일을 맡기기 전 값이라 나중에는 되살릴 수 없다. 묻는 법은 interview.md 끝. 주인이 답한 값만 저장한다.
```bash
node <skill-dir>/scripts/baseline.mjs --main <main> --id ad-log --minutes 40 --note "엑셀 합계까지"
```
6) 첫 업무라면 **일요일 성적표를 등록**한다(11절). 주인에게 "매주 일요일 21:50에 성적표를 보내 드려요"라고 알린다.

## 2. 사례 받기 (총괄)

"지난번에 직접 하신 결과물 3개만 보내 주세요. 엑셀·캡처·카톡 그대로 괜찮아요."
사례마다 **"이때는 왜 이렇게 판단하셨어요?"** 를 묻는다. 이게 제일 중요하다. 주인 머릿속 기준이 여기서 글자로 나온다. 새로 나온 기준은 설명서 5절에 넣자고 제안한다.
```bash
node <skill-dir>/scripts/case.mjs --main <main> --id ad-log --title "11/3 광고 일지" \
  --input-file /tmp/in.txt --judgment "B 캠페인은 시작 3일 안 돼서 표시 안 함" --output-file /tmp/out.txt
```
판단 이유가 비면 저장되지 않는다(exit 2). 사례가 없으면 "이번 주에 한 번 직접 하시면서 화면을 캡처해 주세요."

## 3. 되말하기 (담당 직원 = L0 견습)

담당 직원이 **설명서와 사례만 읽고**, 자기 말로 순서를 설명하고 **가장 헷갈리는 곳 2개**를 묻는다.
```
📊 <직원 이름> — 제가 이해한 '<업무>'
1. … (단계마다 한 줄)
가장 헷갈리는 곳 2개
① …?
② …?
```
이걸 보고로 기록하고 주인에게 보낸다(4절 명령에 `--kind talkback`). 주인이 틀린 곳을 짚으면(✏️) 5절 순서로 설명서를 고치고 다시 되말한다. "틀린 곳 없음"(👍)이면 7절 승급 제안.
주인에게 덧붙인다: "제가 헷갈린 곳은 설명서에 빠져 있던 곳이에요. 목요일 발표 소재로 좋아요."

## 4. 보고 기록 (담당 직원, 일을 마칠 때마다)

설명서대로 일을 한 뒤, 주인에게 보고를 보내고 같은 내용을 기록한다.
```bash
node <skill-dir>/scripts/report.mjs --main <main> --id ad-log --title "11/9 광고 일지" --body-file /tmp/report.md [--kind report|talkback|replay|teach]
```
보고 끝에 항상: **"👍 / ✏️ 고칠 점 한 줄 / ❌ 틀린 점 한 줄로 채점해 주세요."** 대시보드가 있으면 "대시보드 「수습」에서 눌러 주셔도 돼요." 대시보드에 보이게 하려면 dashboard-builder 7절(빌드 → 전송)을 이어서 한다.

## 5. 채점 받기 (총괄 또는 담당)

입구는 셋, 결과는 같다.
| 주인이 | 실행 |
|---|---|
| 대화에서 "👍" / "✏️ 광고비는 VAT 빼고" | `grade.mjs --main <main> --id ad-log --ref <보고 rid> --grade good\|fix\|bad --note "<한 줄>"` |
| `[채점] … (id report:…)` 문장을 붙여 넣음 | `grade.mjs --main <main> --text "<문장 그대로>"` |
| "대시보드 채점 가져와" | dashboard-builder `send_to_pc.mjs … --grades-only`(또는 `--with-grades`)로 채점 파일을 받아 → `grade.mjs --main <main> --from <그 파일>` |

- ✏️·❌ 인데 이유가 없으면 저장되지 않는다(exit 2) → "어디를 고치면 될까요? 한 줄만 알려 주세요."
- **✏️·❌ 를 받으면 반드시 이 순서:**
  1. 가설: "제가 틀린 이유는 ○○ 같아요." (설명서의 어느 절이 빠졌거나 흐렸는지)
  2. 수정안: 설명서를 어떻게 고칠지 바뀌는 문장만 보여 준다.
  3. 주인 승인 → `job.mjs --file <고친 설명서> --lesson "<배운 것 한 문장>" --reason "보고 ✏️"`
  4. "다음부터 이렇게 할게요." 거절되면 다른 가설로 다시 묻는다.
- 👍 에 `eligible: true` 가 오면 7절로 승급을 제안한다.

## 6. 재현 시험 (L1 따라하기, L3 다시 보기)

**새 대화(새 세션)** 에서 담당 직원이 설명서만 보고 사례를 하나씩 다시 푼다. 사례의 결과는 보지 않고 입력만 본다. 푼 결과를 `report.mjs --kind replay` 로 올리고 주인이 원래 결과와 비교해 채점한다. 연속 3건 👍 이면 통과. 다르게 나온 곳은 5절대로 설명서를 고친다.

## 7. 승급 (총괄)

승급은 기분이 아니라 채점표로. 조건은 `level.mjs check` 가 판단한다.
| 지금 단계 | 통과 조건 |
|---|---|
| L0 견습 | 되말하기 👍 |
| L1 따라하기 | 재현 시험 연속 👍 3건 |
| L2 같이 하기 | 실제 보고 연속 👍 5번 |
| L3 혼자 하기 | 재현 시험 연속 👍 3건 + '먼저 묻기' 1개를 '하고 나서 보고'로 옮김(8-1) |
| L4 가르치기 | 다른 직원이 이 설명서만 보고 1건 처리해 👍(9절) |

조건을 채우면 **먼저 제안**한다: "'쿠팡 광고 일지'가 승급 조건을 채웠어요(보고 연속 👍 5번). L3 혼자 하기로 올릴까요?" → 주인 "응/승급시켜 줘":
```bash
node <skill-dir>/scripts/level.mjs --main <main> --id ad-log promote --approved
```
승인 없이 `--approved` 를 붙이지 않는다. 주인이 "승급시켜 줘"라고 해도 조건이 안 되면 exit 3 → "아직 ○○이 남았어요"라고 지금 진행을 알려 준다.

## 8. 묻기 규칙 (boundary.md)

- 새 규칙: 주인이 "광고 끄는 건 꼭 먼저 물어봐" → `boundary.mjs --add "광고 끄기" --section ask`
- **8-1 믿음이 쌓였을 때(L3):** 주인이 "광고 일지 기록은 묻지 말고 해도 돼" → `boundary.mjs --move "광고 일지 기록" --to after`. 비서가 먼저 제안해도 된다: "최근 5번 연속 그대로 쓰셨어요. 기록은 묻지 않고 하고 나서 보고할까요?"
- `never`(절대 하지 않기)에 있는 일은 주인이 시켜도 한 번 확인한다.

## 9. 둘째 직원 · 가르치기 (L4)

같은 일을 다른 직원에게 넘길 때는 처음부터 인터뷰하지 않는다.
```bash
node <skill-dir>/scripts/start.mjs --main <main> --id ad-log-2 --title "쿠팡 광고 일지(재고팀)" --agent <둘째 직원 id> --copy-from ad-log
```
둘째 직원이 설명서만 보고 1건 처리 → 원래 업무에 `report.mjs --id ad-log --kind teach` 로 올리고 주인이 채점. 👍 면 원래 업무 L4 통과(수료). 둘째 직원은 3절(되말하기)부터 자기 수습을 시작한다.
**한 번에 한 명씩.** 첫 직원이 L2 쯤 됐을 때 둘째를 시작하자고 권한다.

## 10. 현황

"수습 현황 보여 줘" → `status.mjs --main <main>` 의 `message` 를 그대로. 채점 기다리는 보고가 있으면 "어제 보고 2건이 채점을 기다리고 있어요"라고 한 줄 덧붙인다.

## 11. 주간 성적표 (총괄)

매주 일요일 21:50, 업무마다 처리 건수 · 내가 고친 횟수 · 그대로 쓴 비율 · 아낀 시간을 지난주와 비교해 보낸다. 숫자는 채점 기록에서만 나온다. 주인에게 새로 묻지 않는다.
```bash
node <skill-dir>/scripts/metrics.mjs --main <main> --weekly
```
- 출력 `message` 를 **그대로** 보낸다. **비어 있으면 아무것도 보내지 않는다.** 숫자를 고치거나 해석을 지어내지 않는다.
- **아낀 시간은 추정**이다: 기준 시간 × (👍 + ✏️ 건수) − 검토 시간(👍 1분 · ✏️ 5분 · ❌ 10분, 어림값). 정확한 값처럼 말하지 않는다.
- 되말하기·재현 시험은 연습이라 세지 않는다. ❌ 는 아낀 시간에 넣지 않는다.
- 기준 시간이 없다고 나오면 1절 5)의 질문을 한 번 묻는다.
- 대시보드를 쓰면 같은 숫자가 「수습」 메뉴 그래프로 보인다. dashboard-builder 7절로 전송한다.

등록은 처음 한 번. 먼저 `openclaw cron list` 로 `job-handoff-weekly` 가 있는지 보고, 없을 때만:
```bash
openclaw cron add --name job-handoff-weekly --agent main --cron "50 21 * * 0" --tz Asia/Seoul \
  --channel telegram --to <주인 텔레그램 chatId> --announce \
  --message "job-handoff 스킬 11절(주간 성적표)을 실행해. message 가 비어 있으면 아무것도 보내지 마."
```
`--channel last` 는 쓰지 않는다. 텔레그램과 디스코드가 둘 다 연결돼 있으면 등록이 거부된다. chatId 를 모르면 주인에게 텔레그램으로 말을 걸어 달라고 하고 확인한다. 등록 형태는 설치된 버전의 `openclaw cron add --help` 로 확인한다. 등록 뒤 시각과 채널을 주인에게 보여 준다.

## 12. 오류가 나면

| exit | 뜻 | 주인에게 |
|---|---|---|
| 2 | 이유·확인이 필요함(✏️❌ 한 줄 / 사례 판단 이유 / 승인 없음 / 기준 시간 값·변경 확인) | 출력 `error` 의 앞 문장(쉬운 말)을 그대로 묻는다 |
| 3 | 승급 조건이 아직 안 됨 | "아직 ○○이 남았어요" + `level.mjs check` 의 진행 |
| 4 | AGENTS.md 안내 구역이 망가짐 | "업무 규칙 파일의 수습 안내 부분이 깨져 있어서 손대지 않았어요. 확인해 주세요" |

## 경계

- 업무 폴더(`jobs/<id>/`)와 AGENTS.md 의 표시 구역(`job-handoff-hook`) 밖은 고치지 않는다. 원래 AGENTS.md 는 처음 고칠 때 `AGENTS.md.job-handoff.bak` 으로 남는다.
- 설명서의 옛 판은 `versions/` 에 남는다. 지우지 않는다.
- 묻기 규칙의 '먼저 묻기' 일은 승급과 상관없이 먼저 묻는다. 돈이 들거나 바깥으로 나가는 일은 늘 먼저 묻는다.
- 안내를 빼려면 `hook.mjs --main <main> --remove`(업무 폴더와 기록은 남는다).
